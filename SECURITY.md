# Security Policy

Garage OS supports business operations. Reports involving authentication, authorization, personal information, transaction integrity, deployment, or other sensitive behavior must be handled privately.

## Reporting a vulnerability

- If the repository offers **Report a vulnerability** under GitHub's **Security** tab, use that private reporting channel.
- If private reporting is not enabled, contact the repository maintainer through an established private channel before sharing technical details.
- **Do not publish** exploitation details, credentials, private user information, internal network details, or production screenshots in public GitHub issues or pull requests.
- Describe affected versions or commits, expected versus actual behavior, and safe reproduction steps using synthetic test data only.

## Safe testing

Only test systems and environments you own or have explicit permission to assess. Do not probe the production Garage Coffee application, payment integrations, staff accounts, or other people's data.

## Supported versions

The maintainers have not yet published a stable supported-version matrix or a coordinated disclosure response timeline. This document will be updated before the first general-purpose open-source release.
